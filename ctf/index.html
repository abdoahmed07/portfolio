What solving these challenges actually taught me, framed the way it'd come up in a conversation.

💉
SQL Injection
Parameterized queries prevent it by treating user input strictly as data, never as SQL syntax. String concatenation is dangerous specifically because it lets user input change the structure of the query itself.
💥
Buffer Overflows
Stack layout puts the return address right after local variables. Overwriting it redirects execution. Defenses: stack canaries (detect the overwrite), ASLR (randomize addresses), and the NX bit (make the stack non-executable).
🔑
Encoding vs. Encryption
Encoding (base64, ROT-13) has no secret key, a keyspace of 1, and provides zero security. Encryption uses a secret key with a keyspace large enough to resist brute force. Confusing the two is a common and dangerous mistake.
🗂️
File Forensics
Office documents (docx, pptx, xlsx) are ZIP archives of XML and media. Hidden data can live in non-standard files inside that archive. Tools like binwalk, exiftool, and strings are standard for finding it.
🧭
CTF Methodology
Reconnaissance first: view source, check robots.txt, look for exposed files, before trying anything exploit-shaped. Most of the challenges here rewarded looking carefully before attacking.
