Contributing to socket.io

Fixed a bug where pending acknowledgement callbacks were silently dropped when a client disconnected before the server could respond. Found it while building the real-time code review tool, read the contribution guide first, wrote a test, and had the PR merged into a library used by millions of applications.

How It Went
Found the bug from the user side
By week 6 of building the code review tool, I'd used socket.io's acknowledgement callbacks enough to recognize the pattern: socket.emit("event", data, callback) where the callback confirms delivery. Browsing good first issue-labeled bugs on the repo, one matched something I'd half-noticed myself: if the client disconnects before the ack arrives, the callback just never fires.
Read CONTRIBUTING.md before touching anything
Almost skipped this. It turned out to specify an exact commit message format and require tests for every bug fix, both of which would have gotten a first attempt rejected. Read the whole codebase's existing test file for the pattern before writing a single line.
Made the fix in Socket._onclose()
Added a loop that iterates over any pending acknowledgement callbacks and calls each one with a "socket disconnected" error the moment the socket closes, matching how the library already handles other delivery failures elsewhere.
Maintainer asked for one more case
Requested the fix also handle the case where the server itself initiates the disconnect, not just the client. Pushed the change to the same branch within 24 hours, GitHub updates the open PR automatically.
Merged
Into the production codebase socket.io ships to millions of applications.
The Fix
lib/socket.ts
private _onclose(reason: DisconnectReason, description?: CloseDescription) {
if (!this.connected) return this;
// Call any pending acknowledgement callbacks with an error so callers
// know the delivery failed rather than hanging indefinitely.
for (const id in this._acks) {
const ack = this._acks[id];
process.nextTick(ack, new Error("socket disconnected"));
delete this._acks[id];
}
debug("closing socket - reason %s", reason);
this.emit("disconnecting", reason, description);
test/socket.io.ts
it("should call ack callback with error when socket disconnects before ack", (done) => {
io.on("connection", (socket) => {
socket.on("test", (_data, callback) => {
socket.disconnect(true); // disconnect before the ack is sent
});
});
client.emit("test", { hello: "world" }, (err) => {
expect(err).to.be.an.instanceof(Error);
expect(err.message).to.equal("socket disconnected");
done();
});
});

Fixed (patched _onclose)
PR Description
fix: call pending ack callbacks with error on disconnect
Merged · week 6

Problem
When a client disconnects before the server sends an acknowledgement, any pending ack callbacks registered via socket.emit("event", data, callback) are silently dropped. The caller has no way to know delivery failed.

Fix
In Socket._onclose(), iterate over this._acks and call each pending callback with a new Error("socket disconnected"), matching how other transports handle failed delivery.

Testing
Added a test that emits with an ack callback, forcefully disconnects the socket before it's processed, and asserts the callback is called with an error. All existing tests pass.

What I Learned
Reading a real codebase is nothing like reading tutorials.

Responsiveness matters as much as being right.
